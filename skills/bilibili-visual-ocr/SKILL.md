# Bilibili Visual OCR

Operate only inside AudioSpider's existing SQLite and bundle workflow at
`/root/code/github_repos/AudioSpider-fork`. Do not create a second dataset tree.

Preserve these distinctions:

- `caption.tracks` is only for Bilibili platform captions and keeps its
  `platform_manual`, `platform_auto`, or `platform_unknown` provenance.
- Pixel-derived text belongs only in `derived_text.visual_ocr` with
  `text_source=visual_ocr`, `extraction_kind=automatic`, and
  `caption_authorship=unknown`.
- OCR cannot determine whether the original burned-in subtitle was written by
  a human or generated by AI.

Before a real run, read [references/runbook.md](references/runbook.md). Use the
repository's dry-run, job lock, sidecar validator, full bundle fingerprint, and
SQLite compare-and-swap. Never edit MP4/WAV payloads during backfill.

Use the isolated `audiospider-ocr` environment. Do not install PaddleOCR into
the stable `audiospider` environment. Initialize the model once, use one GPU
worker on the L4, and clear Cookie, token, secret, and proxy variables from OCR
subprocesses.

Platform captions always have priority. Run visual OCR only when the refreshed
same-language platform result is still absent or unusable. Treat
`no_stable_text_detected` as an extractor outcome, not proof that the video has
no visible subtitles.

For an exact multispeaker batch, select only completed Bilibili manifest jobs with
`visual_ocr_fallback=true` and their bound `visual_ocr_profile`; use exact job keys and preserve
`batch_id`, six-cell category, and `candidate_unverified` review state. OCR text cannot upgrade speaker,
language, rights, AI-generation, or human-review claims.

The preceding formal Bilibili download and any failed-row retry must use
`main.py --batch-id multispeaker-video-100-20260912`; OCR backfill itself remains exact-job-key scoped.
